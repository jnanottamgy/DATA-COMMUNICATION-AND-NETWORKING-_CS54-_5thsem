01

What a network actually is

A network is just devices joined by links so they can exchange data. That's all.

Formally: a network is the interconnection of a set of devices capable of communication. Everything in this course is a detail of how that exchange is organised.

Two kinds of device — this distinction matters all term

TypeWhat it isExamples
Host
(end system)		A device that produces or consumes the data. The message starts or ends here.Laptop, desktop, phone, server, security system
Connecting deviceA device that only moves data along. It never creates the message.Router (joins networks), switch (joins devices), modem (changes the form of data), hub, repeater

A node is any device that can send and/or receive data — it covers both kinds.

Why you care: the exam repeatedly asks "how many layers is each device involved in?" The answer depends entirely on this split — a host runs all 5 layers, a router only 3, a switch only 2. A connecting device doesn't need the top layers because it never reads the message, only the envelope.

The four connecting devices, by layer

DeviceLayerWhat it does
Repeater1 PhysicalAmplifies / regenerates a weak signal to extend range. Understands nothing — just boosts.
Hub1 PhysicalConnects devices and broadcasts to all ports, no filtering. Dumb.
Switch2 Data linkForwards only to the correct device using the MAC address.
Router3 NetworkRoutes between different networks (LAN ↔ Internet) using the IP address.
AnalogyA hub shouts your message into a crowded room and hopes the right person hears. A switch walks it to the right desk in the office. A router takes it to a different building.
HookThe higher the layer, the smarter the device. Repeater 1, Hub 1, Switch 2, Router 3.

The journey of one message — the picture to hold in your head

Everything in Units 1, 2 and 3 is one slice of this single journey. When a question confuses you, locate it on this line first.

The words on that picture

TermMeaning
LANLocal Area Network. Privately owned, one office / building / campus. Joins hosts.

The one sentence that makes layering click

Look at the picture again. The message ("GET me this web page") only matters at the two ends. Every box in the middle doesn't care what the message says — it only needs to know where to send it next.

That is exactly why the stack is split into layers. The top layers are the conversation; the bottom layers are the delivery. Middle boxes implement only the delivery layers, so they stay cheap and fast.

AnalogyYou post a letter. The letter is for your friend. The postal workers never open it — they only read the envelope, and each one only needs to know the next sorting office, not the whole route. The letter is the application layer; the envelope is everything below.
HookEnds talk, middles forward. Application / transport / network are end-to-end. Data link / physical are hop-to-hop.

03

What a protocol is, and why anyone bothered with layers

A protocol is a set of rules that the sender, the receiver and every device in between agree to follow.

Not code, not hardware — an agreement. "Port 80 means web traffic." "A line containing only a full stop ends an email." "Reply 200 OK if you found the file." Both sides must already know the rules, or the bytes are meaningless.

The textbook story — Maria and Ann (worth knowing, it's examinable)

Scenario 1 — face to face. Two neighbours talk in the same language. Communication happens in one layer. Their protocol has 5 rules: greet on meeting; keep vocabulary to the level of the friendship; don't speak while the other speaks; it's a dialog not a monolog; exchange nice words on leaving.

Scenario 2 — by post, encrypted. Ann moves away. They now write letters, and encrypt them so an intercepted letter can't be read. Communication now happens in three layers, each with its own machine:

LayerMaria (sender)Ann (receiver)
3Talks to the machine as if it were Ann (plaintext)Machine speaks the plaintext to Ann
2Encrypts plaintext → ciphertextDecrypts ciphertext → plaintext
1Puts ciphertext in an envelope, adds the addresses, mails itTakes the letter out of the mailbox and the envelope

Modularity is the point. If a better encryption comes along they replace only the layer-2 machine. A layer is a black box — you care about its inputs and outputs, never how it works inside. Two machines giving the same output for the same input can replace each other, even from different manufacturers.

The two principles of protocol layering

  1. For bidirectional communication, each layer must perform two opposite tasks, one in each direction (encrypt / decrypt, send / receive).
  2. The two objects under each layer at both sites must be identical (the ciphertext under layer 2 is the same on both sides).

Advantages and the one disadvantage

Advantages: it separates the service from the implementation; and intermediate devices don't need all the layers — without layering they would be as complex as end systems, making everything expensive.

Disadvantage: some argue a single layer would make the job simpler.

Logical connection — a phrase you must be able to define

Layer-to-layer communication is logical, meaning imaginary. Maria's layer-2 machine behaves as if it hands the ciphertext straight to Ann's layer-2 machine. In reality the data goes all the way down, across, and all the way up.

TrapOnly the physical layer really moves anything. Every other "connection" is a convenient fiction. When a question says "explain the logical connections", that sentence is worth a mark on its own.
This unlocksStrike Sheet Q8 (logical connections) and the protocol-layering theory in Unit 1 Section A.
04

Encapsulation — and why the same data has five different names

Going down the stack, each layer wraps what it was given in its own header. Going up, each layer strips its own header off.

That's it. Encapsulation = adding headers on the way down. Decapsulation = removing them on the way up. The data doesn't change — it just collects and sheds envelopes. The five "object" names in the syllabus are simply the same data at five stages of wrapping.

The five names — learn this table cold

LayerObject is calledWhat its header adds
ApplicationMessagenothing yet — this is the user's data
TransportSegment (TCP) or user datagram (UDP)port numbers → which program
NetworkDatagram / packetIP addresses → which computer
Data linkFrameMAC addresses → which next device + error check
PhysicalBitsnothing — it's electricity, light or radio now
HookMy Sister Draws Funny Birds = Message, Segment, Datagram, Frame, Bits.
AnalogyYou write a note (message). You put it in an envelope marked "for the accounts department" (segment — port). You put that in a bigger envelope with the company's street address (datagram — IP). The courier puts that in his bag labelled with the next depot (frame — MAC), and the van drives (bits). At the far end everything is unwrapped in reverse and the note is read.

The two facts people get wrong

1. The MAC address changes at every hop; the IP address does not. The outer bag is re-labelled at each depot, but the company's street address stays on the inner envelope the whole way. This single fact explains why there are two different addresses at all.

2. Headers are overhead. A TCP header is 20 bytes and an IP header is 20 bytes, every single packet. That's why MSS = 1460 = MTU 1500 − 20 − 20, and why UDP's 8-byte header is considered a real advantage over TCP's 20.

Trap"Packet" is used loosely in speech for anything being sent. In an exam answer, use the exact name for the layer you're discussing — segment at transport, datagram at network, frame at data link.
This unlocksStrike Sheet Q8, Q9 (encapsulation figure), Q16 (TCP header), Q19 (UDP header) — and every sentence in the PDF containing the word "segment".
05

The four addresses — and why one is not enough

Each layer has its own kind of address, because each layer answers a different question.

The analogy that fixes this foreverSending a parcel to a friend in a large apartment block:
Hostname = "Rahul's place" — what you call it. Useless to the courier until you look up the actual address.
IP address = the building's street address: 12 MG Road, Bengaluru. Written on the parcel once, never changed.
Port number = the flat number: #402. Gets it to the right person inside the building.
MAC address = the label on the delivery van's bag saying which depot it goes to next. Re-labelled at every depot along the way.

Why this is the single most useful lesson here

Half of the Strike Sheet's sentences are about one of these four addresses:

  • DNS (7 past questions) exists only to turn a hostname into an IP address.
  • Multiplexing / demultiplexing (4 questions) is entirely about choosing the right port.
  • The whole of Unit 3 (14 questions) is about structuring the IP address.
  • Switches vs routers is MAC vs IP.

Quick reference — the OSI and TCP/IP stacks side by side

Two models for the same thing. OSI has 7 layers and is a teaching model. TCP/IP has 5 and is what actually runs the Internet. The syllabus wants both, and the difference is always the same question.

OSI (7)TCP/IP (5)Job in one phrase
7 ApplicationApplicationWhat the user wants
6 PresentationFormat, encrypt, compress
5 SessionManage the conversation
4 TransportTransportRight program, reliably
3 NetworkNetworkRight computer, across networks
2 Data linkData linkRight next device, this link
1 PhysicalPhysicalBits on the medium

Session and presentation are missing from TCP/IP. Two reasons: (1) TCP/IP has more than one transport protocol and some session functions already live inside them; (2) the application layer isn't one piece of software, so an app that needs session or presentation features builds them in itself.

Why OSI never took over — 3 reasons: it was finished too late (TCP/IP was already deployed with time and money invested), some layers were never fully defined, and it had poor performance when implemented.

HookISO is the organisation. OSI is the model. ISO was founded in 1947; OSI arrived in the late 1970s. Mixing these two up is an easy mark to lose.
AnalogyOSI is the architect's drawing with every room labelled. TCP/IP is the building that actually got built — a few rooms got merged on site.

06

Bits, bytes, octets — and the powers of 2 you must know by sight

A bit is one 0 or 1. Eight bits make one byte. In networking a byte is called an octet.

An IPv4 address is 32 bits = 4 octets, written as four decimal numbers with dots: 192.168.1.10. Each octet is 8 bits, so each can hold 0 to 255 (that is 28 = 256 different values, counting from 0).

The address space is the total number of addresses a protocol can express. With b bits it is 2b. For IPv4: 232 = 4,294,967,296 — about 4.3 billion. That number is the reason the entire second half of Unit 3 exists.

Why 2n and nothing else

Every time you add one bit you double the possibilities. One bit = 2 values. Two bits = 4. Three bits = 8. This is why every block size in Unit 3 is a power of 2 and why a request for 1000 addresses gets you 1024 — there is no such thing as a 1000-address block.

TrapCount from zero. 8 bits give 256 values but the largest is 255. An octet of 301 is invalid; so is a leading zero like 045.

The table to memorise — seriously, memorise it

Those bold ones are the numbers that appear in actual exam questions: 16, 64, 128, 256 (subnet sizes), 1024 (the ISP example), 65,536 (class B), 16,777,216 (class A), 2,097,152 (number of class C blocks).

You will have to convert one octet to binary in the exam. Here is the only method you need.

Binary → decimal

Add the place values under the 1s.

128 64 32 16 8 4 2 1 1 1 0 0 0 0 0 0 = 128 + 64 = 192 128 64 32 16 8 4 2 1 1 1 1 0 0 0 0 0 = 128 + 64 + 32 = 224

This is exactly how you turn a /26 into 255.255.255.192: the prefix leaves 2 ones in the last octet, and 128 + 64 = 192.

08

log2 — what it means and how to do it in your head

log2 N simply asks: "2 to the power of what gives N?" Nothing more.

log2 256 = 8, because 28 = 256. log2 64 = 6. log2 16 = 4. You are reading your powers-of-2 table backwards — that is the entire operation. No calculator, no log tables.

It appears in exactly one formula in your syllabus:

nsub = 32 − log2 Nsub

Which in plain words is: "the prefix length is 32 minus the number of host bits, and the number of host bits is however many doublings it takes to reach the block size."

AnalogyIf 2n is "fold the paper n times", then log2 is "how many folds did that take?" Doubling and halving are the same question asked in two directions.

The lookup you will actually use

Block size N481632641282565121024
log2 N (host bits)2345678910
prefix = 32 − that/30/29/28/27/26/25/24/23/22

Read it right to left and you have the other direction too: a /26 has 32 − 26 = 6 host bits, so 26 = 64 addresses.

HookBigger prefix = smaller block. /24 is 256 addresses; /26 is 64; /28 is 16. The slash counts the network bits, so the more bits the network takes, the fewer are left for hosts.
TrapIf a requirement is not a power of 2, round up. 1000 addresses → 1024 → /22. 50 → 64 → /26. 120 → 128 → /25. You can never allocate exactly 1000, because n would not be a whole number.

10

Why usable hosts = N − 2, and what "network" and "broadcast" addresses are

In every block of N addresses, two are reserved and cannot be given to a device:

  • The first address (all host bits = 0) is the network address. It names the network itself, and it is what a router looks up in its forwarding table to decide which interface to send a packet out of.
  • The last address (all host bits = 1) is the broadcast address. A packet sent to it goes to every host on that network.
usable hosts = N − 2 = 232−n − 2

So a /26 has 64 addresses but only 62 usable; a /28 has 16 but only 14; a class C has 256 but only 254.

AnalogyIn a block of flats, flat numbers run 0 to 63 — but "0" is the name of the building itself on the gate, and "63" is the public address system that reaches every flat. Neither can be a person's home. 62 families can live there.
Trap — this one costs marks every yearWhen a question says "total number of valid IP addresses", the word is ambiguous. Write both: "64 addresses in the block, of which 62 are usable host addresses." You cannot be marked down for the complete answer.
HookFirst and last are always spoken for. First = the network's name, last = shout to everyone.

11

Processes, clients, servers and sockets

Computers don't talk to computers. Programs talk to programs.

  • A program is the file on disk. A process is that program while it is running. Networking happens between processes.
  • A client is the process that starts the conversation by sending a request.
  • A server is the process that is always on, waiting, and sends a response. It has a fixed, well-known address so clients can find it.
  • A socket is the doorway between a process and the network. Socket = IP address + port number.

This is why the transport layer's job is called process-to-process delivery (sometimes service-to-service). The network layer only manages host-to-host — it gets the data to the right machine and stops there.

AnalogyThe IP address gets the letter to the right building, the port to the right flat, and the socket is that flat's letterbox — the slot the program reads from and writes into.

Client-server vs P2P. In client-server, one always-on server with a fixed address serves everyone, and clients never talk to each other. In peer-to-peer (P2P), the hosts talk directly and each peer both downloads and uploads — which is why P2P is called self-scaling: every new peer adds capacity instead of only adding load.

HookThe client knows where the server is; the server does not know where the client is until the client speaks. That's why servers get fixed well-known ports and clients get random high ones.

TrapIn the P2P numerical the peers upload at 300 Kbps and the server at 30 Mbps. If you add 300 + 30 you get a wrong answer. Convert first: 0.3 Mbps. The Strike Sheet flags this; now you know why.
transmission time = L / R = (packet length in bits) / (link rate in bits per second)

A 1 Mbit object onto a 15 Mbps link takes 1/15 s. That is transmission time, not travel time.

The four delays a packet experiences at each hop

DelayCaused by
1 ProcessingRouter examines the header and decides the outgoing link
2 QueuingWaiting in the buffer behind other packets. The only one that varies — this is what causes jitter and what congestion makes worse.
3 TransmissionPushing all the bits onto the link = L / R
4 PropagationThe signal physically travelling down the wire

Traffic intensity = (arrival rate × packet size) / link rate. As it approaches 1, queuing delay grows without bound — that is the whole point of the web-caching numerical, where the access link hits intensity exactly 1.

HookTransmission = how long to get the bits out of the door. Propagation = how long they take to travel. A truck loading (transmission) is separate from the truck driving (propagation).

13

RTT — the unit everything in this course is priced in

RTT (round-trip time) = the time for a small packet to travel from client to server and back.

It includes propagation, queuing and processing delays. Since you cannot make light faster, RTT is the course's fundamental cost unit: protocols are judged by how many RTTs they need.

Opening a TCP connection costs 1 RTT (the first two parts of the handshake); requesting an object and getting it back costs another. Hence the formula running through all of HTTP:

response time per object = 2 RTT + transmit time

And that single formula is why persistent connections were invented: reusing one connection saves the setup RTT on every object after the first. 11 objects: 22 RTT non-persistent, 12 RTT persistent, ~3 RTT pipelined.

Where RTT shows up again

  • TCP's timeout. How long before a sender assumes loss? Slightly longer than one RTT — but RTT fluctuates, so TCP keeps a smoothed average (EstimatedRTT) plus a margin of 4 × DevRTT. That is all Strike Sheet Q14 is.
  • Congestion control. cwnd grows "1 MSS per RTT" in congestion avoidance and doubles every RTT in slow start. The RTT is the clock the algorithm ticks on.
  • Fairness. Connections with a shorter RTT grow faster and grab more bandwidth — a known unfairness in TCP.
AnalogyRTT is the "ping" number gamers complain about. 20 ms feels instant; 300 ms feels broken. Every protocol decision in Units 1 and 2 is really a decision about how many times you are willing to pay that number.
HookCount RTTs, not seconds. When any HTTP or TCP question asks "which is faster and why", the answer is always "because it costs fewer round trips."

TCP vs UDP — the one split the whole of Unit 2 hangs on

The network layer (IP) is unreliable by design. It does its best and makes no promises. Everything TCP does is an attempt to build reliability on top of something that has none.

IP is connectionless and best-effort: each packet is sent independently with no guarantee — it may be lost, duplicated, corrupted or arrive out of order. The transport layer offers two choices about what to do with that.

UDPTCP

AnalogyUDP is shouting across a room — instant, no setup, and if someone didn't catch a word, too bad, the conversation has moved on. TCP is a phone call — you dial, both say hello, and if the line crackles you say "sorry, repeat that". The phone call is more reliable and more expensive to set up.

Why would anyone choose unreliable?

Because reliability costs time, and for some applications a late packet is worse than a missing one. On a video call a frame arriving 2 seconds late is useless — better to skip it. That is the whole argument, and it is worth 5 marks.

The four reasons in your slides:

  1. Finer application-level control — UDP sends immediately; TCP may delay data for setup, congestion control or retransmission.
  2. No connection establishment — no handshake, no setup delay. This is why DNS uses UDP: a DNS lookup is one tiny question and one tiny answer, and paying a handshake for it would double the cost.
  3. No connection state — no buffers or counters per client, so one server supports far more clients.
  4. Small header — 8 bytes instead of 20.
HookTCP = Takes Care of Packets. UDP = U Don't Pcare. And note: if an app using UDP does need some reliability, it builds it itself, at the application layer.
TrapBoth TCP and UDP do multiplexing/demultiplexing and both have a checksum. Those are the two things they share. Everything else in the table is a difference.

15

Sequence numbers, ACKs, timers and windows — how reliability is actually built

Four simple ideas, combined, give you reliable delivery over an unreliable network. Every single Unit 2 topic is one of these four, examined closely.

1. Sequence number — "this is piece number X"

Number each piece so the receiver can detect a gap, reorder what arrives out of order, and discard duplicates.

The TCP twist that confuses everyone: TCP numbers bytes, not segments. A segment's sequence number is the byte-stream number of its first data byte — so Seq = 100 carrying 5 bytes holds bytes 100 to 104.

2. Acknowledgement (ACK) — "I got up to here"

The receiver sends back a small message confirming receipt. In TCP the ACK number is the next byte expected, not the last one received:

ACK = last byte received + 1

So after the segment above, the receiver replies ACK = 105. And TCP's ACKs are cumulative: ACK = 105 means "everything before byte 105 arrived", not just that one segment. That single property is why a lost ACK is often harmless — the next ACK covers it.

3. Timer — "it's been too long, resend"

If no ACK returns within the TimeoutInterval, the sender assumes loss and retransmits. Setting that interval is the RTT-estimation problem from Lesson 13: too short and you resend data that was merely slow; too long and you sit idle after a real loss.

4. Window — "how much may I have in flight at once?"

The naive protocol is stop-and-wait: send one packet, wait for its ACK, send the next. Correct, but catastrophically slow — you pay a full RTT per packet and the link sits idle throughout.

The fix is pipelining: allow N unacknowledged packets in flight at once. N is the window size. This one idea is behind Go-Back-N, Selective Repeat, flow control and congestion control — all four just answer "what should N be, and what happens when something in the window is lost?"

Tested mostrwnd vs cwnd limit the same thing — data in flight — for different reasons. rwnd protects the receiver from buffer overflow; cwnd protects the network from congestion. The sender obeys the smaller: in flight = min(cwnd, rwnd).
